# 黄推机器人画像

这份文档总结当前样本中较稳定的“批量造号 + 批量发评”模式，用于指导规则设计与后续扩样。

## 1. 账号生成模式

### 1.1 用户名模板

高频形态：

- `英文片段 + 数字尾`
- `英文名/姓氏片段 + 英文片段 + 4-6 位数字`
- `短英文片段 + 4-6 位数字`

示例：

- `JenniferAd89661`
- `StutzTheop73071`
- `MLowler38556`
- `RogerP53288`

观察：

- 很多用户名不像真实手动起名，更像词库拼接后追加随机数字。
- 一部分账号不满足最典型的双片段结构，但仍保留“英文片段 + 数字尾”的生成味道。

### 1.2 昵称模板

高频形态：

- `中文人名/可爱昵称 + 爱心/花朵 emoji`
- `中文人名/可爱昵称 + 导流短语`
- `直接把导流文案塞进昵称`

示例：

- `小奶油❤️`
- `小鱼干❤️`
- `陈思洁❤️无🚪线下`
- `优优酱❤️寻男大固泡`
- `🍑 全推唯一真实约见 💌 附近资源自取`

观察：

- 昵称承担了很强的广告功能。
- 很多账号即使正文只有几个符号，昵称本身也足以表达导流意图。

## 2. 文案生成模式

### 2.1 固定钩子模板

高频句型：

- `来个真人认识一下`
- `有弟弟想认识吗`
- `有没有单身哥哥`
- `找个温柔主人`
- `找个温柔的主人`
- `找个会疼人的哥哥`
- `想有个会疼人的哥哥`
- `找个长期搭子`

观察：

- 这些句子非常短。
- 都是低信息量、高诱导性的钩子文案。
- 真实讨论里很少自然出现这种密集重复模板。

### 2.2 擦边导流模板

高频句型：

- `比她好看的没她骚`
- `比她骚的没她好看`
- `她好涩`
- `我不行了`
- `刷了半天的X，就她的主页能打✈️了`
- `线下sao货没人比她sao`

观察：

- 这类模板更偏擦边和导流暗语。
- 和“真人认识一下”型黄推不同，但仍高度模板化。

### 2.3 短码正文模板

高频形态：

- `emoji + 1-3 位字母数字 + emoji`
- `纯 emoji + 短码`

示例：

- `🚀4x🐇`
- `☀4u🐇`
- `🐏6x🐻`
- `🔅1r🐇🐘`

观察：

- 这类正文几乎不传达自然语言内容。
- 更像是去重标记、绕过重复检测的噪音。

## 3. 昵称导流词库

当前样本里较稳定的昵称导流词：

- `线下`
- `无🚪`
- `找个搭子`
- `蹲一个弟弟`
- `蹲个弟弟`
- `蹲一个哥哥`
- `蹲个哥哥`
- `寻男大固泡`
- `男大固泡`
- `看我主页`
- `真实约见`
- `附近真实约见`
- `约见资源`
- `附近资源自取`
- `附近的DD`
- `全推唯一真实约见`
- `全网唯一约炮社区`
- `点我头像选人`

观察：

- 这批词很多时候比正文更关键。
- 一旦昵称直接导流，正文退化成短码也仍然是强信号。

## 4. 绕过检测手法

### 4.1 零宽字符

常见形式：

- `有没​有`
- `来‌个真人`
- `d‌d个线下的哥哥`

目的：

- 绕过纯字符串匹配。

### 4.2 噪音字符

常见形式：

- 开头加 `x!` `+c` `]` `` ` ``
- 结尾加 `}` `[` `'`

目的：

- 打散重复文本特征。

### 4.3 挂其他账号

常见形式：

- 文案末尾加 `@2018D1`
- 文案末尾加 `@xiaonm88`

目的：

- 可能用于导流、串号、或降低文本重复度。

### 4.4 emoji 混排

常见形式：

- 在句中或句末插入多个随机 emoji

目的：

- 降低模板句的可见重复度。

## 5. 机器人流水线推断

最像的生产流程：

1. 从英文名词库生成用户名，并追加随机数字。
2. 从中文昵称词库生成显示名。
3. 给显示名拼接导流短语。
4. 从若干固定模板句中随机选一句。
5. 自动插入零宽字符、emoji、噪音标点、短码。
6. 在热门帖评论区多账号并发投放。
7. 目标是把用户引流到主页、私信、外链或线下约见。

## 6. 对拦截最有价值的组合特征

单个特征往往不够稳，最有效的是组合判断：

- `昵称像导流广告`
- `用户名像批量号`
- `评论像固定模板句`
- `正文像 emoji+短码噪音`
- `存在主页/约见/线下/弟弟/哥哥/主人等导流词`

可概括为：

```text
模板昵称
+ 模板用户名
+ 模板引流句 / 短码正文
= 高概率黄推机器人
```

## 7. 规则设计建议

- 用户名数字尾只作为辅助信号，不单独触发屏蔽。
- 昵称中的导流词应视为“文本型信号”，而不是普通外观特征。
- 对极短正文单独建模，例如 `emoji + 短码`。
- 针对高频模板句直接建规则，不必过度泛化。
- 新样本优先进入测试集，再决定是否提升为通用规则。
