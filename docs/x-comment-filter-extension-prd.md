# X 黄推评论屏蔽 Chrome 插件需求说明

## 1. 文档信息

- 文档名称：X 黄推评论屏蔽 Chrome 插件需求说明
- 文档类型：PRD / MVP 需求说明
- 适用阶段：0 到 1 的首版开发
- 目标产出：一个可在 Chrome 中安装使用的浏览器插件，帮助用户在浏览 X 评论区时自动识别并折叠疑似黄推回复，并提供快速屏蔽操作

## 2. 背景与问题

X 的热门帖子评论区中常出现大量黄推、引流号、擦边账号和机器人回复。这类内容通常具有以下特征：

- 用户名、昵称、简介含有明显色情或引流关键词
- 头像、封面、用户名风格高度模板化
- 回复内容短、重复、无关原帖
- 常带有诱导点击、导流、私信、付费群、外链等意图
- 多层串联回复，污染正常讨论区

对普通用户来说，平台原生的 `Mute` / `Block` / `Hide reply` 能力存在几个问题：

- 需要人工逐条处理，成本高
- 无法快速批量清理陌生帖子下的黄推评论
- 平台层面的隐藏能力只适用于用户自己发布的帖子
- 用户只是想“看干净一点”，并不一定想永久处理每个账号

因此需要一个本地浏览器插件，在不依赖服务端的前提下，优先解决“评论区观感污染”问题。

## 3. 产品目标

### 3.1 核心目标

- 自动识别 X 评论区中的疑似黄推评论
- 默认折叠或隐藏命中评论，提升评论区可读性
- 允许用户一键对评论账号执行 `Mute` / `Block`
- 提供简单可控的规则配置，避免误伤正常用户

### 3.2 MVP 目标

- 支持在 `x.com` 网页版运行
- 支持识别评论区回复，不要求处理主页时间线
- 支持本地规则判断，不依赖后端服务
- 支持“自动折叠”而非直接彻底删除 DOM，保留用户手动查看能力

### 3.3 非目标

- 不做服务端爬虫或账号托管
- 不尝试平台级删除别人的评论
- 不依赖 AI 审核 API 作为首版必需能力
- 不处理移动端 App
- 不承诺 100% 准确识别所有黄推

## 4. 目标用户

### 4.1 核心用户

- 高频使用 X 的中文用户
- 经常浏览热点、投资、科技类帖子评论区的用户
- 对评论区质量敏感，希望减少色情引流干扰的用户

### 4.2 典型用户诉求

- “我想看评论，但不想一屏全是黄推。”
- “我不想逐条手动 block。”
- “最好插件自动帮我折叠，但让我有权点开看。”
- “如果误判，不要影响正常讨论。”

## 5. 使用场景

### 5.1 场景一：浏览别人热门帖子评论区

用户打开任意热门帖子，插件自动扫描当前已加载的回复列表，将命中的疑似黄推评论折叠，并显示提示：

- `已折叠疑似黄推评论`
- `展开`
- `Mute`
- `Block`

### 5.2 场景二：连续下滑加载更多评论

用户向下滚动时，X 动态加载新评论。插件需持续监听页面变化，对新增评论执行同样判断和处理。

### 5.3 场景三：误判恢复

用户认为某条评论被误判时，可手动展开，并可加入本地白名单，避免后续再次被折叠。

### 5.4 场景四：用户希望更严格或更宽松

用户可在插件设置中调整过滤强度，例如：

- 宽松：仅过滤强色情关键词和明显黄推号
- 标准：过滤大部分黄推与引流号
- 严格：加入头像/用户名模式、低质量重复文案等规则

## 6. 产品方案概述

插件以 Chrome Extension Manifest V3 形式实现，主要通过 content script 注入 `x.com` 页面，对评论区 DOM 进行观察、评分和本地折叠处理。

技术思路：

- 监听页面评论节点渲染
- 提取评论账号与文本特征
- 基于规则计算风险分
- 达到阈值则折叠评论
- 对命中评论注入本地操作 UI
- 用户操作时跳转或触发页面原生交互执行 `Mute` / `Block`

## 7. 功能需求

## 7.1 评论识别与过滤

### 需求说明

插件应自动识别当前帖子的评论与回复内容，并对每条评论进行规则判断。

### 输入特征

- 昵称
- 用户名
- 个人简介（若页面可获取）
- 评论文本
- 评论中是否含外链
- 评论是否为短句、模板句、重复句
- 账号展示内容中的色情 emoji、挑逗文案、导流关键词

### 规则示例

- 色情关键词：如裸露、成人视频、约、福利、看片、私信看图等
- 引流关键词：如 `t.me`、`telegram`、`link in bio`、`onlyfans`、`fansly`
- 用户名模式：随机字母数字、高频成人词组合、明显营销命名
- 简介模式：成人导流、自我营销、收费联系
- 文本模式：与原帖无关、极短、重复、诱导点击主页
- 头像或媒体线索：首版可预留，不作为 MVP 必选

### 输出动作

- 折叠评论内容
- 展示命中原因摘要，如 `命中关键词 + 导流模式`
- 允许用户手动展开

## 7.2 分级过滤策略

### 需求说明

插件需支持基于分数的过滤，而不是单条规则命中即强制隐藏。

### 建议机制

- 每条命中特征赋予一定分值
- 总分达到阈值时折叠
- 高危词直接触发强过滤

### 示例

- 明确色情词：+5
- 导流链接：+4
- 用户名成人词：+3
- 简介导流词：+3
- 评论文本无关且模板化：+2
- 新号特征或异常命名：+2

### 过滤级别

- 宽松：阈值 8
- 标准：阈值 6
- 严格：阈值 4

具体阈值可在开发阶段调优。

## 7.3 本地折叠交互

### 需求说明

被命中的评论默认不应彻底删除，而应折叠为一条占位提示。

### 占位提示内容

- `已折叠疑似黄推评论`
- 命中原因简述
- `展开`
- `本条不再折叠`
- `Mute`
- `Block`

### 设计要求

- 不破坏原始页面布局
- 不影响用户继续滚动
- 风格尽量贴近 X 的原生 UI

## 7.4 一键 Mute / Block

### 需求说明

用户应可对命中账号进行快速屏蔽。

### MVP 建议实现

- 方案 A：模拟点击 X 页面原生菜单，触发 `Mute` / `Block`
- 方案 B：打开账号菜单并高亮提示用户完成最后一步
- 方案 C：批量场景优先采用“本地立即处理”
  - 将本页所有命中账号加入本地黑名单
  - 立即隐藏对应评论

### 约束

- 首版优先使用页面交互，不强依赖 X API
- 若因 DOM 变动导致自动点击不稳定，应保留降级方案
- X 的原生 `Block` 无法真正并行，因为同一时刻只能操作一个菜单和一个确认弹窗
- 因此“真正的一键体验”应通过本地黑名单即时生效来保证；批量按钮不应伪装成无感后台 `Block`

### 推荐交互

- 单条命中评论：保留 `Block` 按钮，执行单账号处理
- 批量处理：提供 `一键隐藏并拉黑本页已拦截`
  - 用户点击后，页面上的命中评论应立即消失
  - 弹窗提示“已加入黑名单并隐藏”

## 7.5 白名单与黑名单

### 需求说明

用户应可覆盖默认规则，减少误判。

### 白名单

- 指定用户名永不折叠
- 指定关键词不过滤

### 黑名单

- 指定用户名始终折叠
- 指定关键词强制折叠

### 存储方式

- 使用 Chrome `storage.local`

## 7.6 插件设置页

### 需求说明

插件需提供最基本的设置页或弹窗配置。

### 设置项

- 开关：启用/禁用插件
- 过滤强度：宽松 / 标准 / 严格
- 是否默认折叠
- 是否显示命中原因
- 白名单管理
- 黑名单管理
- 关键词规则管理

## 7.7 统计与反馈

### 需求说明

插件应向用户展示最基础的本地统计，帮助理解插件效果。

### 建议展示

- 当前页面已折叠评论数
- 今日累计折叠数
- 用户手动恢复的评论数

首版统计仅本地保存，不上传服务端。

## 8. 规则设计要求

## 8.1 规则来源

- 内置默认中文/英文黄推关键词库
- 默认导流域名和平台词库
- 用户自定义规则

## 8.2 规则可维护性

- 规则应结构化存储，避免写死在逻辑代码中
- 支持后续拆分为：
  - 关键词规则
  - 用户名规则
  - 简介规则
  - 文本模式规则
  - 强制命中规则

## 8.3 误判控制

- 单一弱特征不应直接触发折叠
- 正常的成人话题讨论、新闻讨论、医学讨论应尽量避免误判
- 白名单优先级必须高于默认规则

## 9. 非功能需求

## 9.1 性能

- 页面首次加载后 1 秒内完成首屏评论扫描
- 新评论进入视口后应尽快处理，避免用户先看到大量黄推
- 不可明显拖慢 X 页面滚动体验

## 9.2 稳定性

- X 页面 DOM 结构变化时，插件不应导致页面报错或卡死
- 单条评论识别失败不应影响整个页面

## 9.3 隐私

- 首版默认不上传任何用户浏览数据
- 所有规则、统计、白名单本地存储
- 明确告知用户插件不会读取站外账号密码

## 9.4 可维护性

- 识别逻辑与 UI 注入逻辑解耦
- DOM 选择器集中管理
- 规则引擎可独立测试

## 10. 技术要求

## 10.1 推荐技术方案

- Chrome Extension Manifest V3
- `content_scripts` 注入 `x.com`
- `MutationObserver` 监听评论区变化
- `chrome.storage.local` 存储设置和规则
- `options page` 或 `popup` 提供配置界面

## 10.2 建议模块划分

- `content/observer`
  - 监听评论节点变化
- `content/parser`
  - 从 DOM 提取账号与评论信息
- `core/rules`
  - 规则匹配与评分
- `content/filter`
  - 执行折叠与 UI 注入
- `content/actions`
  - 处理展开、白名单、Mute、Block
- `shared/storage`
  - 配置与本地数据读写
- `options/`
  - 设置页面

## 10.3 权限需求

- `storage`
- `activeTab`
- `scripting`
- `host_permissions` for `https://x.com/*`

若不需要动态脚本注入，可评估是否去掉 `scripting`。

## 11. 风险与约束

## 11.1 平台 DOM 变化风险

X 页面结构经常变化，DOM 选择器可能失效。需要：

- 避免依赖脆弱的 class 名
- 优先基于语义属性、可访问性标签、稳定结构定位
- 为解析失败预留容错

## 11.2 自动 Mute / Block 风险

模拟点击 X 原生菜单可能因为：

- 页面结构调整
- 多语言界面文本变化
- 弹层异步加载

而变得不稳定。因此需预留降级方案。

## 11.3 误判风险

若规则过严，可能折叠正常用户评论，影响体验。首版应优先可解释、可恢复，而非激进拦截。

## 11.4 合规风险

插件只能做用户本地视图过滤，不应宣传为“删除平台评论”或“代替 X 官方审核”。

## 12. 验收标准

满足以下条件可视为 MVP 可交付：

- 在 Chrome 中可安装并在 `x.com` 生效
- 打开任意帖子详情页，插件可识别评论区并自动处理新增回复
- 命中评论会被折叠并显示占位说明
- 用户可手动展开被折叠评论
- 用户可将账号加入白名单或黑名单
- 用户可调整过滤强度
- 用户设置在刷新页面后仍生效
- 插件不会造成明显页面卡顿或频繁报错

## 13. 后续迭代方向

## 13.1 V1.1

- 更丰富的规则库
- 多语言黄推识别
- 更稳定的一键 `Mute` / `Block`

## 13.2 V1.2

- 支持主页时间线过滤
- 支持“仅显示高质量回复”
- 支持按关注关系、认证状态、互动质量排序过滤

## 13.3 V2

- 可选 AI 分类器
- 云端同步规则
- 社区共享黑名单

## 14. 开发建议

推荐先做一个最小闭环版本：

1. 仅处理帖子详情页评论区
2. 仅实现规则识别 + 本地折叠
3. 暂不实现复杂的自动 `Mute` / `Block`
4. 先把白名单、强度调节、统计做扎实

这样可以先验证最核心的用户价值：

“用户打开评论区时，黄推是否明显少了，且误伤是否可控。”
